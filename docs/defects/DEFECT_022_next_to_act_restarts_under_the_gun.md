# Defect: `next_to_act` restarts under the gun after a re-raise

**File:** `docs/defects/DEFECT_022_next_to_act_restarts_under_the_gun.md`  
**Date:** 2026-08-18  
**Severity:** Critical  
**Status:** Fixed  
**Introduced in:** present since `next_to_act` was written. Affects every game
on **both** table engines — `casino::table_celled::TableCelled` and the newer
`casino::table::Table` — not only Pluribus replay.  
**Fixed in:** working tree on top of `de2e7508` (pending commit), pkcore `0.6.0`

---

## Summary

Action in poker moves clockwise from whoever set the current bet level.
`SeatsCell::next_to_act` instead began its scan at the under-the-gun seat every
time it was called. Once someone re-raises with players owing chips on *both*
sides of them, the two rules pick different seats — and the engine gave the
action to a player who was not next in turn.

---

## Symptom

The table plays a legal-looking hand in the wrong order. Nothing panics, no
`Result` is `Err`, and the pot balances. Only the sequence is wrong, so every
player after the re-raise acts on information they should not have had, and the
chips land on the wrong seats.

`STATE:153` from the Pluribus corpus is the worked example:

```
STATE:153:fr200fcfc/ccr475cr1200fc/cr5200f:…:-50|-1200|0|1725|0|-475
```

On the flop seat 5 raises to 475, seat 1 calls, and seat 3 re-raises to 1200.
Seat 5 is next in turn and folds. The engine gave the fold to seat 1 instead,
which rotated every remaining action by one live seat and landed seat 3's turn
raise of 5200 on seat 5. Final commitments came out as
`s1 475 / s3 1200 / s5 5200` against the log's `s1 1200 / s3 1200 / s5 475` —
the right three numbers on the wrong three players.

Seven of the ten thousand logged hands are affected: **0.07%**.

### Independent corroboration outside the corpus

`pkarena0-hand-002` in `data/hands/legacy/pkarena0-session_2026-04-15.yaml` is a
captured arena session — a recording of what the engine did, not an authored
expectation. Its preflop log reads:

```text
  seat 5  raise 2333
  seat 4  raise 5900     <-- seat 8 had not acted on the 2333
  seat 5  call
  seat 8  fold
```

Seat 8 was in for 350 and owed 1983 when seat 5 raised to 2333. Clockwise from
seat 5 the next live seat is 8, not 4. Seat 4 acted out of turn, and seat 8 was
then handed a decision it should have made two actions earlier — facing a raise
to 5900 instead of to 2333. **A real player's decision was materially changed by
this defect.**

That recording is a golden file generated by the code it was meant to guard, and
it is the second time in this defect series the same trap has appeared
([`DEFECT_017`](DEFECT_017_omaha_eval_two_card_rule.md) was the first). It is
skipped by `all_hands_replay_consistently` rather than corrected: editing a
recording to say what we now believe should have happened would destroy the only
evidence of what did.

## Root Cause

```rust
    pub fn next_to_act(&self, utg: u8) -> Result<u8, PKError> {
        let current_bet = self.current_bet();
        let everyone_has_bet = self.has_everyone_bet();

        for (i, seat) in self.iter_from(utg).enumerate() {
            …
            if state.is_in_hand() && everyone_has_bet && state.get().amount() < current_bet {
                return Ok(…);
            }
        }
```

The final branch is the correct *predicate* — "still in the hand and owes chips"
— attached to the wrong *origin*. Rooting the walk at `utg` returns the owing
seat that is earliest in under-the-gun order, which is the seat to act only when
every owing seat happens to sit behind the aggressor.

Two things kept it hidden.

**The `everyone_has_bet` gate masks the first trip around.** While anyone is
still `YetToAct`, that seat is returned by an earlier branch, and the wrong
branch is never reached. The defect can therefore only appear on the second trip
— a re-raise into a field that has already acted. That is an uncommon shape, and
it is not the shape anyone writes a fixture for.

**The two rules agree in the overwhelming majority of real hands.** With the
aggressor behind every owing seat — the ordinary case — the UTG scan finds the
first seat after the aggressor by coincidence. 9,993 of 10,000 real hands do not
discriminate. This is the failure mode where a wrong rule and a right rule share
almost all of their outputs, and the sample that separates them is small enough
to look like noise.

## Fix

```rust
        // Action moves clockwise from whoever set the current bet level, not
        // from under the gun. …
        let start = match self.last_aggressor() {
            Some(aggressor) => self.seat_after(aggressor),
            None => utg,
        };
```

with a new `SeatsCell::last_aggressor`:

```rust
    pub fn last_aggressor(&self) -> Option<u8> {
        let current_bet = self.current_bet();
        if current_bet == 0 {
            return None;
        }

        for (index, seat_cell) in self.0.iter().enumerate() {
            let seat = seat_cell.borrow();
            if seat.is_empty() || seat.player.bet.count() != current_bet {
                continue;
            }
            if matches!(
                seat.player.state.get(),
                PlayerState::Blind(_)
                    | PlayerState::Bet(_)
                    | PlayerState::Raise(_)
                    | PlayerState::ReRaise(_)
                    | PlayerState::AllIn(_)
            ) {
                return u8::try_from(index).ok();
            }
        }

        None
    }
```

Only the origin of the walk changes; every branch inside the loop is untouched.

Two properties make this smaller than it looks:

- **`PlayerState::Call` is excluded on purpose.** A caller matches the current
  bet level without setting it, so action does not restart behind them. This is
  the distinction that makes "the seat holding `current_bet`" a well-defined
  single seat rather than a set.
- **Preflop needs no special case.** The big blind's `Blind(100)` *is* the
  current bet level, so `last_aggressor` returns the big blind and the walk
  starts under the gun — which is the correct preflop origin, arrived at by the
  general rule instead of an exception to it. When nobody has bet, `current_bet`
  is `0`, there is no aggressor, and the walk starts at `utg` as before.

## Tests Added

| File | Test name | What it verifies |
|------|-----------|-----------------|
| `src/casino/table_celled/seats.rs` | `next_to_act__starts_clockwise_of_the_raiser` | Second trip around with a mid-field re-raise: the seat to act is clockwise of the raiser, not the earliest owing seat |
| `src/casino/table_celled/seats.rs` | `last_aggressor__is_none_when_nobody_has_bet` | The checked-around case falls back to under the gun |
| `src/casino/table_celled/seats.rs` | `last_aggressor__ignores_a_caller_at_the_same_level` | A caller matching the level is not mistaken for the aggressor |
| `src/analysis/nubibus.rs` | `replay_gives_a_re_raise_the_correct_seat` | `STATE:153` end to end: every losing seat's commitment equals its logged payoff |
| `tests/heavy_tests.rs` | `pluribus__all_games_replay_without_errors` | All 10,000 hands, ~18,500 losing seats checked to the chip |

The first and the last two fail against the old implementation; the two
`last_aggressor` tests pin the helper's contract.

**A first attempt at the unit test did not discriminate.** It re-raised on the
first trip around, where the `everyone_has_bet` gate makes both rules agree. It
passed against the broken code. It is recorded here because that near-miss is the
defect's whole character: the obvious reproduction is the one that does not
reproduce.

---

## Coverage Gap

`next_to_act` had three existing tests, one of them a long twelve-action defect
regression. All three drive a single trip around the table, so none could reach
the branch that was wrong.

The 10,000-hand corpus replay covered the defect and reported success, because it
asserted only that no hand returned an error. **A misrouted action is not an
error** — the table accepts it, the hand completes, and the pot balances. The
strongest-looking evidence in the crate was blind to this entire class of fault
by construction.

The transferable lesson: **an integration test over real data proves nothing
about ordering unless it checks an ordering-sensitive quantity.** The fix here
was to compare each losing seat's committed chips against the payoff the log
records for it. A player who folds loses exactly what they put in, so the two
must agree to the chip — and they cannot agree if the actions landed on the wrong
players.

---

## Prevention

- The five tests above.
- The corpus replay is now ordering-sensitive, so any future change that
  misroutes an action fails immediately with the offending hand printed.
- `last_aggressor` is public and documented, so the ordering rule is now a named,
  testable concept rather than an emergent property of a loop's starting index.
